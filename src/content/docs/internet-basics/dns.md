DNS (Domain Name System) คือระบบที่แปลงชื่อเว็บ เช่น example.com ให้เป็น IP Address ที่คอมพิวเตอร์ใช้เชื่อมต่อกันจริง การเปลี่ยน DNS ช่วยให้ขั้นตอนค้นหาที่อยู่เร็วขึ้นหรือช้าลงได้ แต่ไม่ได้เพิ่มความเร็วดาวน์โหลดหรืออัปโหลดของแพ็กเกจอินเทอร์เน็ต จึงเห็นผลชัดเฉพาะเมื่อ DNS เดิมตอบช้าหรือมีปัญหา
:::

## DNS คืออะไร

คนจำชื่อเว็บได้ง่ายกว่าตัวเลข แต่เครือข่ายส่งข้อมูลด้วย [IP Address](/internet-basics/ip-address/) DNS จึงเป็นเหมือนสมุดโทรศัพท์ของอินเทอร์เน็ต เรารู้ชื่อ ระบบหาหมายเลขให้ เช่นเดียวกับที่เราเปิดชื่อเพื่อนในรายชื่อมือถือแล้วโทรออก โดยไม่ต้องจำเบอร์

DNS ไม่ได้เป็นเครื่องเดียวที่เก็บชื่อทั้งโลก RFC 1034 อธิบายว่าเป็นฐานข้อมูลแบบกระจายเป็นลำดับชั้น (hierarchical) แต่ละส่วนของชื่อดูแลโดยเซิร์ฟเวอร์คนละชุด ชื่อ `www.example.com` อ่านจากขวาไปซ้ายได้ดังนี้

| ส่วนของชื่อ | ระดับ | ความหมาย |
|---|---|---|
| (จุดท้ายสุดที่มองไม่เห็น) | Root | รากของลำดับชั้นทั้งหมด |
| `com` | Top-Level Domain (TLD) | โดเมนระดับบนสุด เช่น com, org, th |
| `example` | Second-level domain | ชื่อที่เจ้าของจดทะเบียน |
| `www` | Subdomain / hostname | ชื่อเครื่องหรือบริการใต้โดเมนนั้น |

## DNS ทำงานอย่างไร

เมื่อพิมพ์ `www.example.com` ในเบราว์เซอร์ ลำดับเกิดขึ้นดังนี้

1. **เช็กแคชในเครื่อง** เบราว์เซอร์และระบบปฏิบัติการจำคำตอบที่เคยถามไว้ ถ้ามีและยังไม่หมดอายุ ใช้ได้ทันที
2. **ถาม recursive resolver** ถ้าไม่มีในแคช เครื่องส่งคำถามไปยัง resolver ที่ตั้งไว้ ซึ่งปกติเป็นเซิร์ฟเวอร์ของผู้ให้บริการอินเทอร์เน็ต หรือ DNS สาธารณะที่ผู้ใช้เลือกเอง resolver ทำหน้าที่สืบหาคำตอบแทนเครื่องจนได้ผลลัพธ์
3. **ถาม Root server** resolver ถาม root ว่าใครดูแล `.com` root ไม่รู้ IP ของ www.example.com แต่ตอบได้ว่า TLD server ของ `.com` อยู่ที่ใด
4. **ถาม TLD server** TLD server ตอบว่า authoritative server ของ `example.com` คือเครื่องใด
5. **ถาม authoritative server** เครื่องนี้เป็นเจ้าของข้อมูลจริงของโดเมน จึงตอบ IP ของ `www.example.com` ได้
6. **ส่งคำตอบกลับและเก็บแคช** resolver ส่ง IP กลับให้เบราว์เซอร์ และเก็บคำตอบไว้ตามเวลา TTL เบราว์เซอร์จึงเชื่อมต่อไปยัง IP นั้นได้

![ลำดับขั้นตอนการค้นหา IP ของ www.example.com ผ่าน DNS](/diagrams/dns-1.svg)

RFC 1034 แบ่งการค้นหาเป็นสองแบบ แบบ recursive คือเซิร์ฟเวอร์รับไปสืบหาคำตอบแทนผู้ถาม ส่วนแบบ iterative คือเซิร์ฟเวอร์ตอบเพียงว่าให้ไปถามใครต่อ ในตัวอย่างข้างต้น resolver ทำงานแบบ recursive ให้เครื่องของเรา และเดินถาม root, TLD และ authoritative แบบ iterative

ตัวอย่างในชีวิตจริง ถ้าเราถามพนักงานต้อนรับของคอนโดว่า "ห้องคุณสมชายอยู่ห้องไหน" พนักงานเดินไปถามผู้จัดการอาคาร ผู้จัดการบอกว่าอยู่ชั้นไหน แล้วเคาน์เตอร์ชั้นนั้นบอกเลขห้อง เราเห็นแค่คำตอบสุดท้าย ส่วนการไล่ถามเป็นหน้าที่ของพนักงาน นั่นคือ resolver

## เซิร์ฟเวอร์ DNS แต่ละประเภททำอะไร

| ประเภท | หน้าที่ | ผู้ดูแล |
|---|---|---|
| Recursive resolver | รับคำถามจากอุปกรณ์ผู้ใช้ สืบหาคำตอบและเก็บแคช | ผู้ให้บริการอินเทอร์เน็ต หรือผู้ให้บริการ DNS สาธารณะ |
| Root server | ชี้ไปยัง TLD server ของโดเมนระดับบนสุดแต่ละตัว | 12 องค์กร (เซิร์ฟเวอร์กระจายหลายประเทศ) |
| TLD server | ชี้ไปยัง authoritative server ของโดเมนที่จดทะเบียนภายใต้ TLD นั้น | ผู้ดูแล TLD (registry) |
| Authoritative server | เก็บข้อมูลจริงของโดเมนและตอบเป็นคำตอบสุดท้าย | เจ้าของโดเมนหรือผู้ให้บริการโฮสต์ DNS ที่เจ้าของเลือก |

IANA ระบุว่าระบบ root ตั้งค่าเป็น 13 ชื่อ (a.root-servers.net ถึง m.root-servers.net) ดูแลโดย 12 องค์กร และแต่ละชื่อมีเซิร์ฟเวอร์จริงกระจายอยู่หลายประเทศ รวมหลายร้อยเครื่อง

## ระเบียนข้อมูล DNS ที่พบบ่อย

ข้อมูลของโดเมนเก็บเป็นระเบียน (record) หลายชนิด RFC 1035 กำหนดชนิดพื้นฐานไว้ เช่น A, NS, CNAME, MX และ TXT

| ชนิด | เก็บอะไร | ตัวอย่างการใช้ |
|---|---|---|
| A | IPv4 address ของชื่อ | www.example.com ชี้ไป 203.0.113.5 |
| AAAA | IPv6 address ของชื่อ | ใช้คู่กับ A เมื่อเว็บรองรับ IPv6 |
| CNAME | ชื่อแฝงที่ชี้ไปยังอีกชื่อหนึ่ง | blog.example.com ชี้ไป example.com |
| MX | เซิร์ฟเวอร์รับอีเมลของโดเมน | ระบุว่าอีเมล @example.com ส่งไปที่ใด |
| NS | authoritative server ของโดเมน | ระบุผู้ดูแลข้อมูลโดเมน |
| TXT | ข้อความอิสระ | ใช้ยืนยันความเป็นเจ้าของโดเมน |

## แคชและ TTL

ถ้าทุกครั้งที่เปิดเว็บต้องเดินถามตั้งแต่ root เครือข่ายจะติดขัดมาก DNS จึงออกแบบให้เก็บแคชทุกระดับ แต่ละระเบียนมีค่า TTL (Time To Live) เป็นจำนวนวินาทีที่กำหนดโดยเจ้าของโดเมน บอก resolver ว่าเก็บคำตอบนี้ไว้ได้นานเท่าไร RFC 1035 กำหนด TTL เป็นเลขจำนวนเต็ม 32 บิต

ผลที่ตามมาคือเมื่อเจ้าของเว็บย้ายเซิร์ฟเวอร์และเปลี่ยน IP ผู้ใช้บางส่วนยังถูกส่งไปที่เก่าจนกว่าแคชจะหมดอายุ จึงนิยมลดค่า TTL ล่วงหน้าก่อนย้าย

## เปลี่ยน DNS แล้วเน็ตเร็วขึ้นจริงไหม

คำตอบตรงๆ คือ **เร็วขึ้นเฉพาะช่วงเริ่มเปิดหน้าเว็บ และเฉพาะเมื่อ DNS เดิมตอบช้า** เหตุผลมีสามข้อ

1. DNS ทำงานก่อนการส่งข้อมูลจริงเท่านั้น หลังได้ IP แล้ว การดาวน์โหลดไฟล์หรือดูวิดีโอใช้แบนด์วิดท์ของแพ็กเกจ ซึ่ง DNS ไม่เกี่ยวข้อง
2. ข้อความ DNS มีขนาดเล็กมากเมื่อเทียบกับหน้าเว็บหรือวิดีโอ (RFC 1035 ฉบับดั้งเดิมจำกัดข้อความผ่าน UDP ไว้ที่ 512 ออกเต็ต) การเปลี่ยน resolver จึงกระทบเฉพาะเวลารอคำตอบของแต่ละการค้นหา ไม่ใช่ปริมาณข้อมูลที่โหลด
3. แคชทำให้ชื่อที่ใช้บ่อยไม่ต้องถามซ้ำ ความต่างของ resolver จึงเห็นเฉพาะการเข้าเว็บที่ไม่เคยเข้ามาก่อน

| อาการ | เปลี่ยน DNS ช่วยไหม |
|---|---|
| เปิดเว็บใหม่ๆ แล้วหน้าค้างตอนแรก จากนั้นโหลดปกติ | อาจช่วย ถ้า resolver เดิมตอบช้า |
| เปิดบางเว็บไม่ได้ แต่เว็บอื่นเปิดได้ | อาจช่วย ถ้า resolver เดิมตอบผิดหรือไม่ตอบ |
| ดาวน์โหลดไฟล์หรือดูวิดีโอกระตุก | ไม่ช่วย ปัญหาอยู่ที่แบนด์วิดท์ สัญญาณ Wi-Fi หรือเส้นทาง |
| เกมมี ping สูง | ไม่ช่วย ping เกมวัดเส้นทางไปเซิร์ฟเวอร์เกม ไม่ใช่เวลาค้นหาชื่อ |
| ทุกเว็บช้าเท่ากันตลอด | ไม่ช่วย ให้ตรวจสาเหตุอื่นก่อน |

ถ้าทดสอบแล้วพบว่าปัญหาไม่ได้อยู่ที่ DNS สาเหตุอื่นของอาการเน็ตช้า เช่น สัญญาณ Wi-Fi อุปกรณ์ และสายสัญญาณ รวบรวมไว้ใน[บทความรวมสาเหตุเน็ตช้าและวิธีไล่ตรวจ](https://aisfibrepro.com/blog/%E0%B8%A3%E0%B8%A7%E0%B8%A1%E0%B8%AA%E0%B8%B2%E0%B9%80%E0%B8%AB%E0%B8%95%E0%B8%B8%E0%B9%80%E0%B8%99%E0%B9%87%E0%B8%95-ais-fibre-%E0%B8%8A%E0%B9%89%E0%B8%B2/)

## วิธีทดสอบว่า DNS ของคุณช้าหรือไม่

ไม่ต้องเดา ทดสอบเองได้ด้วยคำสั่งที่มีในเครื่อง

1. เปิด Command Prompt หรือ Terminal
2. ถาม resolver ปัจจุบัน `nslookup example.com` ดูว่าได้ IP กลับมาหรือไม่
3. ถาม resolver สาธารณะเปรียบเทียบ `nslookup example.com 8.8.8.8`
4. ถ้าต้องการตัวเลข ใช้ `dig example.com` และ `dig @8.8.8.8 example.com` (macOS / Linux) แล้วเทียบบรรทัด "Query time" บน Windows ใช้ PowerShell `Measure-Command { Resolve-DnsName example.com -Server 8.8.8.8 }`

ทำซ้ำหลายรอบต่างเวลากัน เพราะผลแกว่งตามภาระของเครือข่าย ถ้า resolver เดิมตอบใกล้เคียงกันและได้ IP ถูกต้อง การเปลี่ยนไม่ได้อะไรเพิ่ม

## DNS สาธารณะที่เป็นตัวเลือก

Google Public DNS เป็นตัวอย่างบริการ DNS สาธารณะที่เปิดให้ใช้ฟรี เอกสารของ Google ระบุที่อยู่ IPv4 ไว้สองค่า คือ `8.8.8.8` และ `8.8.4.4` นอกจากนี้ยังมีผู้ให้บริการรายอื่น ให้เลือกเทียบ

ข้อควรพิจารณาก่อนเปลี่ยน

- **นโยบายข้อมูล** DNS resolver เห็นชื่อเว็บทุกแห่งที่อุปกรณ์ค้นหา จึงควรอ่านนโยบายความเป็นส่วนตัวของผู้ให้บริการที่เลือก
- **เครือข่ายภายใน** บางเครือข่ายใช้ resolver ของผู้ให้บริการเพื่อชื่อเฉพาะภายใน เช่น ระบบบริการของผู้ให้บริการเอง การเปลี่ยนอาจทำให้ใช้บริการเหล่านั้นไม่ได้
- **ตำแหน่งของ resolver** บางเว็บส่งผู้ใช้ไปเซิร์ฟเวอร์ที่ใกล้ resolver ที่ถาม ถ้า resolver อยู่ไกล อาจถูกพาไปเซิร์ฟเวอร์ที่ไม่ใกล้ผู้ใช้ ผลนี้ขึ้นกับแต่ละเว็บ

## DNS แบบเข้ารหัส (DoH)

DNS ดั้งเดิมส่งคำถามแบบข้อความธรรมดา ผู้ที่อยู่ระหว่างทางอ่านได้ว่าเปิดเว็บใด DNS over HTTPS (DoH) ตาม RFC 8484 ส่งคำถาม DNS ภายใน HTTPS ทำให้เนื้อหาคำถามถูกเข้ารหัสระหว่างเครื่องกับ resolver เบราว์เซอร์และระบบปฏิบัติการสมัยใหม่รองรับเป็นตัวเลือก ผลคือความเป็นส่วนตัวของคำถามดีขึ้น ไม่ได้ทำให้เน็ตเร็วขึ้น และ resolver ปลายทางยังเห็นชื่อที่ถามเช่นเดิม

## วิธีเปลี่ยน DNS

จุดที่เปลี่ยนได้มีสองระดับ

- **ที่ เราเตอร์** เปลี่ยนครั้งเดียว มีผลกับทุกอุปกรณ์ที่ได้ DNS จาก เราเตอร์ (เข้าหน้าตั้งค่า เราเตอร์ หา DNS Server หรือ WAN DNS)
- **ที่อุปกรณ์** เปลี่ยนเฉพาะเครื่องนั้นในการตั้งค่าเครือข่ายของระบบปฏิบัติการ ใช้แทนค่าที่ได้จาก เราเตอร์

ก่อนเปลี่ยนให้จดค่าเดิมไว้เผื่อต้องย้อนกลับ หลังเปลี่ยนควรล้างแคชเพื่อให้ผลทดสอบถูกต้อง บน Windows ใช้ `ipconfig /flushdns`

## คำถามที่พบบ่อย

### DNS ล่มคืออะไร ทำไมต่อเน็ตได้แต่เปิดเว็บไม่ได้

อาการคือสัญญาณเน็ตปกติ แต่เบราว์เซอร์ขึ้นว่าหาเซิร์ฟเวอร์ไม่พบ เพราะ resolver ไม่ตอบหรือตอบผิด ลองสั่ง ping 8.8.8.8 ถ้าตอบกลับปกติแต่เปิดเว็บด้วยชื่อไม่ได้ แสดงว่าเครือข่ายใช้ได้และปัญหาอยู่ที่การแปลงชื่อ ให้ลองเปลี่ยน resolver (ดู[วิธีใช้ ping](/troubleshooting/ping-traceroute/))

### เปลี่ยน DNS ช่วยให้เล่นเกมลื่นขึ้นไหม

โดยทั่วไปไม่ช่วยตอนเล่น เพราะเกมเชื่อมต่อไปยัง IP ของเซิร์ฟเวอร์เกมที่ได้มาแล้ว ความหน่วงระหว่างเล่นขึ้นกับเส้นทางไปเซิร์ฟเวอร์ ผลของ DNS เกิดเฉพาะตอนหาที่อยู่ในครั้งแรก

### DNS กับ IP ต่างกันอย่างไร

IP คือหมายเลขปลายทางที่ใช้ส่งข้อมูลจริง ส่วน DNS คือระบบที่แปลงชื่อเป็น IP

### ต้องล้างแคช DNS เมื่อไร

เมื่อเว็บเพิ่งย้ายเซิร์ฟเวอร์แต่เครื่องยังเปิดไปที่เก่า หรือหลังเปลี่ยน DNS แล้วต้องการทดสอบผลใหม่ แคชหมดอายุเองตาม TTL อยู่แล้ว การล้างเป็นการข้ามช่วงรอ

### DNS สาธารณะปลอดภัยกว่าของผู้ให้บริการไหม

ไม่มีคำตอบตายตัว ความปลอดภัยและความเป็นส่วนตัวขึ้นกับนโยบายและการดำเนินงานของ resolver แต่ละราย ควรอ่านเงื่อนไขของผู้ให้บริการที่เลือก
